# Founder Studio: what we reuse from the existing code (Phase S0)

Written on 2026-10-12. Every function name below was checked against the code on that date. "In progress" means the
file is in the working tree but not committed yet. Nothing here is built yet; this is the plan for which existing
function each Studio phase calls, and why.

The rule: if the repo already computes something, Studio calls it. Studio never keeps a second copy of a formula, a
ledger, a decision log or an approval rule.

## 2. What we need that does not exist, or does not fit

1. **The evidence ledger** (`src/uwcopilot/evidence`) is being built in Phase 4. Studio S4 extends it; it does not
   write its own.
2. **The risk client and service do not match.** `risk/client.py` posts a `scenario` field that the service forbids,
   and the service's response does not validate against the client's response model. So the client cannot get a
   successful score today (found with a test probe in the Phase 1 code map). A fix is planned in the Phase 5
   additions. Studio does not depend on it, because of item 6.
3. **No revenue or rate levers in `risk/scenario.py`.** The plan's S3 text says the lender stress preset reuses "the
   same revenue-drop / rate-rise levers" from `risk/scenario.py`. Those levers are not there. They are the fixed
   shocks in `agent/policy_credit.py` and the planned Phase 4 grid in `evidence/scenarios.py`. S3 uses those.
4. **No policy for a new business.** The SYNTHETIC Northwind policy needs a complete run of monthly bank statements
   to verify revenue, and it has minimum time-in-business rules (plus a separate restaurant rule). A pre-revenue
   founder never passes them. Options are listed in [open_questions.md](open_questions.md).
5. **No application fields for a startup.** `CreditApplication` forbids unknown fields and has no projection fields.
   Its SYNTHETIC industry list (`CREDIT_INDUSTRIES`) covers a bakery, a full-service restaurant and a hardware retail
   store, but not a car wash, motel, short-term rental or laundromat. S6 needs a versioned schema change.
6. **No applicable risk model.** The Phase 1 credit model uses consumer Lending Club fields and is not trained here
   (no Kaggle key). The insurance models are French motor models. Neither fits a founder's business. Any model-PD
   claim for a founder file is UNKNOWN, with that reason. No score is made up.
7. **Two reviewer roles only.** S7 needs four. Phase 5 additions plan an authorization module.
8. **No Hugging Face provider** in the LLM layer, and Hugging Face is blocked here.
9. **No Studio data, no geospatial library, no web toolchain in CI.** See [data_sources.md](data_sources.md) and
   [architecture.md](architecture.md) section 8.
